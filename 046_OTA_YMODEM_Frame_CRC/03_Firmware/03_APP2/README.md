# STM32F411 APP2: YMODEM CRC and Application Firmware Update Experiment

## Project Description

##### Introduction

APP2 is the update target in [project 046](../../README.md), built from APP1. It keeps the same HAL/FreeRTOS OTA and CRC functions; its status log and LED timing identify the application after installation.

##### Main Features

- Receive encrypted YMODEM packets with USART1 DMA and two synchronized buffers.
- Check full-frame CRC-16/XMODEM before handing data to the external flash write task; padding participates in CRC but is not stored.
- Commit package length and EEPROM state `0x22`, then request a reset through the update command and key confirmation. Bootloader performs decryption and installation.
- Report `App2 running...` and toggle PC13 with a 200-tick loop delay. No whole-file CRC is calculated.

##### Repository Structure

```text
Core/, Drivers/     HAL peripherals and device support
Middlewares/        FreeRTOS
Middlewares_User/   YMODEM, CRC, logging and RTT
BSP/, SysSupport/   Storage, UART, debug and RTOS setup
Tasks/APP/          LED and application status task
Tasks/SWC_OTA/      Download state machine and flash write task
MDK-ARM/            Keil project
```

## Usage Guide

##### Environment and Dependencies

STM32F411CEU6, W25Q SPI flash, AT24C02 EEPROM, USB-to-UART and J-Link; Keil MDK 5.38 / ARMCC 5.06 update 7, an AES packaging tool, a HEX command sender, SecureCRT or another YMODEM sender, and RTT Viewer. HAL, FreeRTOS, libcrc, EasyLogger and SEGGER RTT are included.

##### Hardware Connection and Configuration

Use 3.3 V logic and a common ground; cross-connect UART TX/RX.

| Interface | Configuration |
|---|---|
| USART1 | PA9 TX / PA10 RX; 115200 baud, 8N1, no flow control |
| W25Q SPI1 | PA4 CS / PA5 SCK / PA6 MISO / PA7 MOSI |
| AT24C02 software I2C | PB8 SCL / PB9 SDA; retain bus pull-ups |
| Status and input | PC13 LED; PA0 active-low key |

Both APPs link to `0x08008000` and use a 1 kHz RTOS tick. Downloads occupy external region A (`0x000000–0x00FFFF`, 64 KiB). Keep Bootloader at `0x08000000`.

##### Build, Run, and Observe

1. Build `MDK-ARM/STM32F411CEU6.uvprojx` at `0x08008000`. Encrypt the latest APP2 BIN into `../04_BIN_EncryptionBIN/APP2_EncryptionBIN.mxxx` (generated by rebuilding).
2. Start from an installed [APP1](../02_APP1/README.md). Send HEX `11 22 33`; after `C`, transfer the APP2 encrypted package by YMODEM. Close the old serial connection before changing tools.
3. Wait for HEX `44 55 66` and `OTA ready … EEPROM state=0x22`, then send HEX `77 88 99` and press the key within about 20 seconds.
4. APP1 resets into Bootloader, which decrypts and installs APP2 at the same application address. Confirm `App2 running...` and the approximately 200 ms PC13 toggle interval in place of APP1's marker.

| Application | Status log | Delay after each LED toggle / log |
|---|---|---|
| APP1 | `App1 running...` | 500 ticks, approximately 500 ms |
| APP2 | `App2 running...` | 200 ticks, approximately 200 ms |

Both use a 1 kHz FreeRTOS tick. Their C/H files differ only in `Tasks/APP/app.c`; the OTA and CRC implementations are shared.

APP2's purpose in this test is to verify that the new application was installed and launched. Its retained OTA receiver supports further updates, but this run ended at APP2. The APP1 → APP2 hardware test passed on 2026-10-07; CRC-mismatch injection was not performed.

##### Porting Notes

Keep the APP link base, Bootloader handoff/vector address, flash partitions, EEPROM metadata, AES package format and UART settings consistent. Adapt HAL peripherals, DMA and RTOS interrupt priorities for another board. This project is verified on STM32F411CEU6.
